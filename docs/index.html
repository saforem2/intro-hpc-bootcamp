👋 Welcome

This is a hands-on introduction to doing AI on supercomputers. It starts from the ground up (the shell, Python, and how HPC systems work) and builds all the way to training large language models across many GPUs. Almost every page is a runnable notebook: you can read it here, open it in Google Colab, or run it on an HPC system.

Tip🎯 Who this is for

Students and researchers who are new to AI, HPC, or both. You don’t need prior machine-learning experience. Comfort with basic programming helps, but the first few pages (Using Python, Working with Data) bring you up to speed.

🚦 Start here

Work through the five parts in order. Each builds on the last:

  1. [0] Intro to AI and HPC — compute systems, the scheduler, Python, and data; then your first models (Monte Carlo, linear regression, clustering). New? Start with Compute Systems ➡️
  2. [1] Neural Networks — from a single neuron to CNNs, representation learning, and distributed training.
  3. [2] Large Language Models — how LLMs work, then build and train a GPT from scratch and learn to evaluate it.
  4. [3] Advanced / Large-Scale LLMs — MoE, pretraining at scale, fault tolerance, post-training, and RL for reasoning.
  5. [4] AI for Science — the payoff: the same Transformer + HPC stack applied to genomes, proteins, and molecules.
Note🖥️ Where the code runs

The lighter notebooks run anywhere (including a laptop or Google Colab; look for the badge at the top of each page). The large-scale training examples are meant for an HPC system. The bootcamp uses Jupyter on NERSC Perlmutter (project m4388), but the commands are scheduler-agnostic and work on ALCF PBS systems too. See running instructions below.

🏔️ Running instructions

🔬 On Perlmutter (NERSC)

This is the machine we use during the bootcamp.

Important📦 Nothing to install

Every package these notebooks need — torch (CUDA), transformers, ezpz, bootcamp, plotly, nltk, bertviz — is already in a shared conda environment that all of m4388 can read:

/global/cfs/cdirs/m4388/envs/intro-hpc-bootcamp

You do not run pip install, conda create, or uv anything. Clone the notebooks, point Jupyter at the kernel, and start working.

1. Get the notebooks. From a Perlmutter terminal (jupyter.nersc.gov → Perlmutter Login Node → Terminal, or ssh <user>@perlmutter.nersc.gov):

# your own directory inside the project space -- do NOT work in a shared clone,
# and do not edit someone else's
mkdir -p /global/cfs/cdirs/m4388/projects/project8/$USER
cd       /global/cfs/cdirs/m4388/projects/project8/$USER

git clone https://github.com/saforem2/intro-hpc-bootcamp
cd intro-hpc-bootcamp

You now have your own copy to edit and break freely. $SCRATCH or $HOME work just as well if you would rather keep it there — nothing below depends on where the clone lives.

2. Make the shared kernel visible. One-time setup, then log out and back into Jupyter so the file is re-read:

echo 'export JUPYTER_PATH=/global/cfs/cdirs/m4388' >> ~/.bashrc

3. Open a notebook and pick the kernel. In the Jupyter file browser, open any content/**/index.ipynb, then choose the kernel:

Intro to HPC Bootcamp

That environment already has torch (CUDA), transformers, ezpz, bootcamp, plotly, nltk, bertviz, and the rest of the stack these pages import.

🌐 Distributed Training Example

Ready to train a real model across multiple GPUs? The full end-to-end walkthrough (request an interactive job, set up the environment, and launch a multi-node run with ezpz launch) lives on the dedicated pages, complete with annotated output:

  • 🧠 [1.4] Distributed Training — the concepts (DDP, FSDP, collective ops, 3D parallelism) and a complete Perlmutter run you can reproduce, including a full annotated training log.
  • 🚀 [2.1] Parallel Training — the same ideas applied to pretraining a GPT with wordplay.
TipTL;DR: launch a run

On an HPC system with an interactive allocation:

# 1. set up the environment (system-agnostic; on Perlmutter just activate the
#    shared env instead -- see the step-by-step below)
source <(curl -fsSL https://bit.ly/ezpz-utils) && ezpz_setup_env
uv pip install "git+https://github.com/saforem2/ezpz"

# 2. verify the distributed setup
ezpz test

# 3. launch 2D-parallel training (auto-detects SLURM srun / PBS mpiexec)
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 2 --train-iters 100

Full step-by-step (Perlmutter)

This runs a 2D-parallel (tensor/sequence parallel + FSDP) training job on a Llama-style model, straight out of ezpz — no repo to clone and nothing to install, since ezpz is already in the shared environment.

  1. Login to Perlmutter:

    ssh <user>@perlmutter.nersc.gov

  2. Request an interactive job (4 A100s per node, charged to the GPU account m4388_g):

    NODES=2 ; HRS=02 ; QUEUE=interactive
salloc --nodes $NODES --qos $QUEUE --time $HRS:30:00 \
       -C 'gpu' --gpus=$(( 4 * NODES )) -A m4388_g

  3. Activate the shared environment:

    module load conda
conda activate /global/cfs/cdirs/m4388/envs/intro-hpc-bootcamp

  4. Verify the distributed setup before spending an allocation on a real run:

    ezpz test

    ezpz discovers the job from SLURM, so you should see one line per rank and a WORLD_SIZE equal to your total GPU count (8 for the 2-node job above).

  5. Launch 2D-parallel training:

    ezpz launch python3 -m ezpz.examples.fsdp_tp \
    --model small \
    --tp 2 \
    --dataset random \
    --seq-len 1024 \
    --batch-size 8 \
    --train-iters 100

    ezpz launch auto-detects the scheduler (SLURM → srun, PBS → mpiexec) and fills in the rank/host bookkeeping, so there is no srun -n $NGPUS to get wrong.

Tip🎛️ What the flags mean
flag meaning
--tp 2 tensor-parallel degree. Must divide WORLD_SIZE; the remaining ranks (WORLD_SIZE / tp) become the FSDP data-parallel dimension. With 8 GPUs and --tp 2 you get 2-way TP × 4-way FSDP.
--model small size preset (debug, small, medium, large, xl, …) instead of setting --dim/--n-layers by hand. Start at debug if you just want it to finish fast.
--dataset random synthetic tokens, so there is no dataset download or filesystem I/O. Swap in any HuggingFace repo id to train on real text.
--batch-size 8 per-DP-rank micro-batch. Global batch = --batch-size × (WORLD_SIZE / --tp).

Other flags worth knowing: --activation-checkpoint to trade compute for memory, --compile for torch.compile, and --pytorch-profiler if you want a trace. Run python3 -m ezpz.examples.fsdp_tp --help for the full list.

Note📈 Try scaling it

The interesting exercise is watching what changes as you vary the parallelism without changing the model:

# same 8 GPUs, three different splits of TP vs FSDP
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 1 --train-iters 50
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 2 --train-iters 50
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 4 --train-iters 50

More TP means less memory per GPU but more communication per step. Where the crossover lands depends on your model size and interconnect — which is exactly the tradeoff [3.1] Pretraining at Scale works through.

<details closed><summary><h3>Full step-by-step (Perlmutter)</h3></summary>

This runs a **2D-parallel** (tensor/sequence parallel + FSDP) training job on a
Llama-style model, straight out of `ezpz` — no repo to clone and nothing to
install, since `ezpz` is already in the shared environment.

1. Login to Perlmutter:

    ```bash
    ssh <user>@perlmutter.nersc.gov
    ```

1. Request an interactive job (4 A100s per node, charged to the GPU account
   `m4388_g`):

    ```bash
    NODES=2 ; HRS=02 ; QUEUE=interactive
    salloc --nodes $NODES --qos $QUEUE --time $HRS:30:00 \
           -C 'gpu' --gpus=$(( 4 * NODES )) -A m4388_g
    ```

1. Activate the shared environment:

    ```bash
    module load conda
    conda activate /global/cfs/cdirs/m4388/envs/intro-hpc-bootcamp
    ```

1. Verify the distributed setup before spending an allocation on a real run:

    ```bash
    ezpz test
    ```

    `ezpz` discovers the job from SLURM, so you should see one line per rank and
    a `WORLD_SIZE` equal to your total GPU count (8 for the 2-node job above).

1. Launch 2D-parallel training:

    ```bash
    ezpz launch python3 -m ezpz.examples.fsdp_tp \
        --model small \
        --tp 2 \
        --dataset random \
        --seq-len 1024 \
        --batch-size 8 \
        --train-iters 100
    ```

    `ezpz launch` auto-detects the scheduler (SLURM → `srun`, PBS → `mpiexec`)
    and fills in the rank/host bookkeeping, so there is no `srun -n $NGPUS` to
    get wrong.

::: {.callout-tip title="🎛️ What the flags mean" collapse="true"}
| flag | meaning |
|:--|:--|
| `--tp 2` | tensor-parallel degree. Must divide `WORLD_SIZE`; the remaining ranks (`WORLD_SIZE / tp`) become the FSDP data-parallel dimension. With 8 GPUs and `--tp 2` you get 2-way TP × 4-way FSDP. |
| `--model small` | size preset (`debug`, `small`, `medium`, `large`, `xl`, …) instead of setting `--dim`/`--n-layers` by hand. Start at `debug` if you just want it to finish fast. |
| `--dataset random` | synthetic tokens, so there is no dataset download or filesystem I/O. Swap in any HuggingFace repo id to train on real text. |
| `--batch-size 8` | *per-DP-rank* micro-batch. Global batch = `--batch-size × (WORLD_SIZE / --tp)`. |

Other flags worth knowing: `--activation-checkpoint` to trade compute for
memory, `--compile` for `torch.compile`, and `--pytorch-profiler` if you want a
trace. Run `python3 -m ezpz.examples.fsdp_tp --help` for the full list.
:::

::: {.callout-note title="📈 Try scaling it" collapse="true"}
The interesting exercise is watching what changes as you vary the parallelism
*without* changing the model:

```bash
# same 8 GPUs, three different splits of TP vs FSDP
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 1 --train-iters 50
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 2 --train-iters 50
ezpz launch python3 -m ezpz.examples.fsdp_tp --model small --tp 4 --train-iters 50
```

More TP means less memory per GPU but more communication per step. Where the
crossover lands depends on your model size and interconnect — which is exactly
the tradeoff [\[3.1\] Pretraining at Scale](./03-advanced-llms/1-pretraining-at-scale/)
works through.
:::
